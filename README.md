# Laminar on Railway

A one-click Railway template for [Laminar](https://github.com/lmnr-ai/lmnr), the open-source observability and evals platform for AI agents. It deploys **Laminar v0.3.4** with the full stack from upstream's `docker-compose-full.yml`: RabbitMQ for span processing and Redis for cache and pub/sub, plus Postgres, ClickHouse and Quickwit.

| Service | Built from | What it does | Volume |
|---|---|---|---|
| **Laminar** (public) | `laminar/` · `caddy:2.11.9-alpine` | The one public URL. Puts the dashboard behind a login and sends `/v1/*` (SDK and OpenTelemetry ingestion, checked against project API keys) to the app server | none |
| **Frontend** | `frontend/` · `ghcr.io/lmnr-ai/frontend:v0.3.4` | Next.js dashboard. Runs the Postgres and ClickHouse migrations and creates the Quickwit indexes on boot | none |
| **App Server** | `app-server/` · `ghcr.io/lmnr-ai/app-server:v0.3.4` | Rust server: trace ingestion (HTTP 8000, gRPC 8001), queue workers, realtime updates (8002) | none |
| **ClickHouse** | `clickhouse/` · `clickhouse/clickhouse-server:26.5.7.64` | Spans, traces, evaluations and the SQL editor's data | `/var/lib/clickhouse` |
| **Quickwit** | `quickwit/` · `quickwit/quickwit:v0.9.1` | Full-text search over spans | `/quickwit/qwdata` |
| **RabbitMQ** | `rabbitmq/` · `rabbitmq:4.2.9-alpine` | Queues spans between ingestion and processing, so a restart doesn't drop accepted spans | `/var/lib/rabbitmq` |
| **Postgres** | Railway Postgres | Users, workspaces, projects, API keys, datasets | Railway volume |
| **Redis** | Railway Redis | Cache and pub/sub shared by the dashboard and the app server | Railway volume |

Every image is pinned by version and digest in its folder's `Dockerfile`. Each service's root directory is its folder.

## Variables

Every secret is generated by Railway (`${{secret(...)}}`) and every address is a reference variable over the private network, so the template asks for nothing.

| Service | Variable | Value |
|---|---|---|
| Laminar | `LAMINAR_USERNAME` | `admin`: dashboard login user |
| Laminar | `LAMINAR_PASSWORD` | generated: dashboard login password |
| Laminar | `FRONTEND_HOST`, `APP_SERVER_HOST` | private domains of Frontend and App Server |
| Frontend | `DATABASE_URL`, `REDIS_URL`, `CLICKHOUSE_*`, `QUICKWIT_SEARCH_URL`, `BACKEND_URL`, `BACKEND_RT_URL` | references |
| Frontend | `NEXTAUTH_SECRET`, `SHARED_SECRET_TOKEN`, `AEAD_SECRET_KEY` (64 hex), `CLICKHOUSE_POSTGRES_PASSWORD` | generated |
| Frontend | `NEXTAUTH_URL`, `NEXT_PUBLIC_URL`, `PUBLIC_API_BASE_URL` | `https://` + the Laminar service's domain |
| App Server | `DATABASE_URL`, `RABBITMQ_URL`, `REDIS_URL`, `CLICKHOUSE_*`, `QUICKWIT_*`, `NEXT_INTERNAL_URL` | references |
| App Server | `SHARED_SECRET_TOKEN`, `AEAD_SECRET_KEY` | same values as Frontend |
| ClickHouse | `CLICKHOUSE_PASSWORD`, `CLICKHOUSE_RO_PASSWORD` | generated: admin user `laminar` and read-only user `laminar_ro` |
| RabbitMQ | `RABBITMQ_DEFAULT_PASS` | generated: user `laminar` |

Optional, add them yourself on **Frontend** and **App Server**: `LLM_PROVIDER` (`openai`, `gemini`, `bedrock`, ...) and `LLM_API_KEY` for chat-with-trace and SQL-with-AI. On **Frontend**: `AUTH_GITHUB_ID`/`AUTH_GITHUB_SECRET` (or Google, Azure AD, Okta, Keycloak) for OAuth sign-in. See [Laminar's configuration reference](https://laminar.sh/docs/self-hosting/configuration).

## After deploying

1. Wait until every service is green. The first boot runs the database migrations (1–3 minutes).
2. Open the Laminar service's URL. Log in with `admin` and the `LAMINAR_PASSWORD` shown in the Laminar service's **Variables** tab.
3. On Laminar's sign-in page enter your email, then create a workspace and a project.
4. In the project settings, create a project API key.
5. Point the SDK at your domain over HTTPS:

```python
from lmnr import Laminar
Laminar.initialize(project_api_key="YOUR-API-KEY", base_url="https://YOUR-DOMAIN", http_port=443, force_http=True)
```

```ts
import { Laminar } from "@lmnr-ai/lmnr";
Laminar.initialize({ projectApiKey: "YOUR-API-KEY", baseUrl: "https://YOUR-DOMAIN", httpPort: 443, forceHttp: true });
```

Any OpenTelemetry OTLP/HTTP exporter works too: `https://YOUR-DOMAIN/v1/traces` with the header `Authorization: Bearer YOUR-API-KEY`.

Self-hosted Laminar signs in any email address without a password, so the gateway login is what protects the dashboard. Share it only with people who should see every trace.

## Updates

This template builds from this repository. When a new Laminar release comes out we bump the pinned images here and note it in [CHANGELOG.md](CHANGELOG.md). Railway then shows an "update available" notice on your project, and you choose when to apply it. The dashboard runs any new migrations on its next boot.

## Testing

`test/compose.yml` runs the same images with the same settings locally (`docker compose -f test/compose.yml up -d --build`), and `test/smoke.sh` checks the login gate, sign-in, a project API key, one trace ingested and read back with SQL.
